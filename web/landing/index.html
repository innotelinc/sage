It listens, watches, reads, then decides.

Four ways in, one persona out. Everything it perceives is folded into the same memory, so a slide and a sentence from ten minutes ago can answer the question being asked now.

🎙

Listening

Live lecture transcript through on-device speech recognition, chunked into notes that keep definitions, numbers and the words EXAM: — everything the instructor stressed.

🖥

Watching

Screen share, phone camera, or an uploaded screen recording. Frames are sampled and read as they change, so a whiteboard becomes notes while it is being written.

📖

Reading

Slides, photographs, handouts and pasted chapters become study notes with the formulas exactly as given, likely exam questions, and the gaps the material leaves.

⚖️

Evaluating

It commits to an answer with a confidence score and the reason it knows, rather than hedging. Ambiguity gets the most likely reading and one clause saying so.

✍️

Writing

Quizzes answered one decision at a time, and essays with a real argument — citing only the material you supplied, never inventing a reference.

🧬

Evolving

After class it reviews its own notes and rewrites its behaviour: how this instructor grades, which answer shape earned marks, how you like to sound.

What it can actually capture.

No hand-waving: a web page cannot read an iPhone screen or a cast stream. Here is exactly what works, checked against what the browser exposes.

SourceCapturableHow
Android Chrome — whole phone screenyesWatch → pick the screen, including other apps
Desktop browser — tab, window or screenyesWatch → pick the surface
Mirrored iPhone (AirPlay to a Mac/PC)yesWatch the mirroring window
iPhone screen directlynoiOS has no capture API — use Control Center recording, then Read the video
Camera — board, projector, TVyesAim
TV cast stream (Chromecast / AirPlay)noThe stream never reaches the page — aim the camera, or capture on the receiving computer
Worksheet, textbook pageyesPhoto → Answer or Read

Mic and screen capture need a secure context: https:// or localhost. A bare LAN address loads the interface but not the capture.

One gateway, every model.

SAGE speaks plain OpenAI-compatible HTTP, so the gateway is a base URL and a key — nothing else. This build ships wired to Innotel OmniRoute.

  • Endpoint — https://gateway.innotel.us/v1
  • Verified model — agy/gemini-3-flash, text and vision in about a second
  • Keys — subscribe.innotel.us
  • Anywhere else — OpenAI, Groq, OpenRouter or a local Ollama, via AI_BASE_URL
The key's allowlist is the real contract. The gateway lists 1,249 models, but a key routes only the connections it is scoped for. On this key every audio model sits behind an openrouter connection that is excluded, so server transcription answers 403 — SAGE detects that once and falls back to on-device speech recognition instead of retrying forever.
verify any model before trusting it
$ curl -s https://gateway.innotel.us/v1/chat/completions \
    -H "authorization: Bearer $KEY" \
    -H "content-type: application/json" \
    -d '{"model":"agy/gemini-3-flash","messages":[{"role":"user","content":"OK"}]}'

Runs on what you already have.

Plain Node with no dependencies, or a Cloudflare Worker — the same src/app.mjs handler serves both. The phone app is the same page, added to the home screen.

🧩

Persona is a file

src/persona.mjs holds the identity rules and one contract per task: note, answer, quiz, essay, read, phrase, evolve.

🔐

Secrets stay server-side

The key lives in .env, gitignored and never served — the browser only ever talks to your own API.

📱

Installable

A PWA with a manifest and offline shell. Add to Home Screen and it opens standalone, with its own icon.
